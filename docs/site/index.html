Write the step once. Reference it everywhere.

YAML pipelines grow by copy and paste — there is no way to say this step, the one I already wrote. HCL has references. cinzel converts between the two, in both directions.

.github/workflows/ci.yaml
name: CI
on:
  push:
    branches: [main]
jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Test
        run: go test ./...
cinzel/ci.hcl
job "build_and_test" {
  id = "build-and-test"

  runs_on {
    runners = "ubuntu-latest"
  }

  steps = [
    step.checkout,
    step.test,
  ]
}

step.checkout is a real reference. Rename the block and every job using it follows. Write a step once and ten jobs share it. GitHub and GitLab still read only YAML, so cinzel converts back.

Both directions

unparse turns the pipeline you already run into HCL. parse turns it back. Start from what you have.

Comments survive

Above a block, beside a value, closing a body. The note saying why a version is pinned is still there after the round trip.

Pinned to SHAs

pin rewrites every action tag as the commit it points at, keeping the tag in a comment. upgrade bumps, then pins.

Drift fails the build

diff reports what parse would change and writes nothing. Exit 1 on drift, 2 if it could not run.

Two providers

GitHub Actions — workflows, composite actions, the step graph. GitLab CI/CD — jobs, templates, includes.

Refuses rather than guesses

HCL that would produce YAML the platform rejects stops with an error naming the problem.

Commands

cinzel github unparse -d .github/workflows YAML you already run → HCL.
cinzel github parse -d cinzel HCL → the YAML the platform reads.
cinzel github diff Fails the build when the committed YAML has drifted.
cinzel github pin Every action tag becomes the SHA it points at.
cinzel gitlab unparse -f .gitlab-ci.yml Same two directions, GitLab's keywords.
cinzel github assist -p "go PR with tests" A pipeline from a prompt, converted the usual way.
