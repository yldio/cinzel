One step, four copies, two of them wrong

ci.yaml - uses: actions/checkout@v4
release.yaml - uses: actions/checkout@v4
nightly.yaml - uses: actions/checkout@v3
docs.yaml - uses: actions/checkout@v4 with: persist-credentials: true

YAML has no way to say this step, the one I already wrote. So you write it again. The third copy is a version behind and the fourth leaves a token on disk, and nothing anywhere says so.

cut once

A step is a block.
Every job points at it.

# cinzel/steps.hcl — written once step "checkout" { uses { action = "actions/checkout" version = "11d5960a3267" # v4 } } # cinzel/jobs.hcl — and wherever it is needed job "ci" { steps = [step.checkout, step.test] } job "release" { steps = [step.checkout, step.build] } job "nightly" { steps = [step.checkout, step.soak] } job "docs" { steps = [step.checkout, step.site] }

Bump the version in one place and all four move. Rename the block and every reference follows. GitHub and GitLab read only YAML, so cinzel github parse writes it back — comments, key order and all.

both directions
cinzel github unparse
The pipeline you already run, turned into HCL. Start from what you have, not a blank file.
cinzel github parse
Back to the YAML the platform reads. Comments survive the trip — above a block, beside a value, closing a body.
cinzel github diff
Says what parse would change and writes nothing. Exit 1 when the committed YAML has drifted, 2 when it could not run.
cinzel github pin
Every action tag becomes the commit it points at, tag kept in a comment. upgrade bumps first, then pins.
cinzel gitlab …
The same two directions for .gitlab-ci.yml — jobs, templates, includes, the pipeline keywords.
cinzel github assist
A pipeline from a prompt, through the same path your own YAML takes. What you already have is referenced, not duplicated.
